# 实施路线

## M0：结构与需求初稿（已完成）

交付模块目录、项目说明、需求、产品设计、架构、数据模型与决策记录。校验文件与链接，不把目录骨架描述为可运行应用。

完成条件：文档可用于讨论；已提出需求与建议分开；关键未决问题清晰。

## M1：首条设备与采集链路（进行中）

已完成代码骨架：Vue 页面、Tauri 命令、独立 Rust 业务核心、类型化网关、demo 适配器与基础测试。真实 ADB、OCR、数据库和 Agent 接入未完成；名称查询演示不等于游戏采集。

以 Windows/macOS + MuMu + 国服为目标，验证现有 piagent/Codex 的图像与非交互调用能力；建立可启动的 Tauri + Vue 界面与 Agent 适配器接口。完成设备枚举、截图预览、手工录入、一张截图的识别校对与 SQLite 保存。

完成条件：真实目标设备可连接；档案保存后重启可读取；失败与取消有明确反馈。收集代表性截图并按 [名称校准与识别评估](recognition-evaluation.md) 验证名称 OCR、歧义处理、截图素材关联及用户修正路径，不引入头像匹配实验。

## M2：从者库、素材与编队

完成分页采集候选、实例合并确认、素材裁剪、筛选详情和队伍编辑。支持无关卡保存及关卡关联。首版统一实现概念礼装、御主礼装、助战和 COST 校验；礼装数据先支持手工录入与本地条目选择，费用和上限记录游戏识别或人工确认来源。

完成条件：重复持有与重扫不会破坏档案；素材可重用；编队及礼装/助战配置可持久化并恢复；COST 覆盖达限、超限、未知数据与助战免计费；同一持有礼装重复装备会提示。

## M3：战况与 Agent 建议

定义支持的战斗页面和状态字段，接入约定 Agent/模型，展示带来源的状态与建议。处理未知页面、模型超时和过期截图。

完成条件：真实战斗样本可重放；建议与快照一致；不确定状态明确显示。

## M4：按已确认需求扩展

自动翻页先做小范围可行性验证；可复用现有能力且可靠时可提前加入 M1/M2，否则不阻塞首版。后续推进更多区服与分辨率、多账号管理、备份导出以及接近游戏的视觉和拖拽体验。战斗执行不在当前需求内。功能顺序由实际使用反馈决定。

## 验证原则

按阶段添加有意义的测试：数据合并与关系约束用单元/集成测试；识别用固定截图数据集；设备操作用适配器模拟加真实设备联调；桌面打包在目标操作系统验证。截图样本不默认提交玩家原始数据，优先使用已整理且允许入库的样本。
