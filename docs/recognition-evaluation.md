# 名称校准与截图素材识别方案

当前决策：仅引入官方从者中／日名称资料，识别游戏内名字并与名称表校准；头像和立绘全部来自游戏截图。不建立官方头像图库，不做官方或本地头像模板身份比对。此方案取代先前的多外观图片检索建议。尚无真实样本实测结果。

## 数据边界

名称表仅包含稳定内部 ID、中／日官方名称、必要的来源及版本信息，不下载官方图片或完整技能/培养图鉴。同一身份可有多条经来源核实的官方显示名；游戏中是否随状态改变名字需用实机样本核实，不由模型编造别名。OCR 常见错字不写入官方名称表。

头像、详情立绘和其他缩略图按用途从游戏截图裁剪，关联到用户确认的持有实例，保留截图与裁剪区域。外观无需命名或匹配官方外观编号。缺图显示占位，用户可重新采集。图像哈希只用于文件去重。

## 识别与校准流程

1. 玩家打开包含从者名字的页面并截图。识别模块定位名称区域，保留原始文本和截图证据。
2. 规范化首尾空白、全半角和已验证的等价标点；保留原文，不删除可能区分身份的称号、括号或后缀。规范化产生碰撞时保留全部候选。
3. 用中／日名称表精确检索；失败时以编辑距离等文本方法给出候选。精确命中也要检查是否一名多条；模糊结果不自动定案。
4. 展示原始识别文本、候选中／日名称和截图，供用户校准。可重新识别名称区域、手工编辑文本检索或选择名称条目。
5. 用户确认更新哪份持有实例或新增实例。名字校准只解决名称归属，不解决重复持有；即使名称唯一，也不能据此自动合并档案。
6. 独立识别等级、宝具、再临和技能字段；裁剪头像/立绘并预览关联。确认后保存，重试不重复提交。

只有头像而无可读名字的页面不凭图猜身份：提示打开详情页，或由用户关联已有档案。战斗中的身份可使用用户确认的实际出战槽位关联；计划编队未确认同步到游戏时不能直接当作当前阵容。无法关联的单位仍可保留血量等可观察状态，身份标记未知。

## 歧义与降级

- 名字被遮挡、截断或字体识别失败：请求完整名称页或手动输入，不强行选最近候选。
- 同名条目或中／日映射不唯一：保留多候选，由用户结合游戏详情选择；如果仅有名称资料仍无法区分，保留未解析身份和独立本地实例，不声称完成校准。
- 新从者或缺少正式显示名：保存待校准原始名称和截图，允许先管理本地档案；名称表更新后重新校准，不能按新表静默合并记录。
- 同一从者的多份持有：用户明确选择更新目标，跨页会话变化时重新确认。
- 更换头像、立绘或灵衣：重新截图裁剪即可，不改变已确认身份与培养状态，不增加身份匹配负担。

## 使用者修正路径

从者详情提供“重新识别名字”“重新识别培养信息”“手动校准名称”“重新采集头像/立绘”四类入口。截图失败或取消时保留旧记录；识别结果先显示新旧差异，用户选择接受哪些字段。头像和立绘分别预览/重新裁剪，更新素材不顺带覆盖培养数据。

身份改绑前显示受影响的档案和编队引用，确认后只修改目标实例的名称关联，保留稳定实例 ID；旧培养字段和素材标记待复核，不能自动当作新身份的正确资料。不得把两个持有实例自动合并。保留修正记录与上一版素材/字段引用，支持撤销本次修正；发生后续编辑时先比较版本，避免撤销覆盖新数据。

## 评估计划

重点从图片相似度改为名称 OCR 与候选校准：覆盖中／日文本、长名、符号、相似名称、同名多条、名字变化、列表截断、新名称缺失及重复持有。国服实际截图为主；日文样本若仅为合成文字，应单独报告，不能据此声称已验证日服支持。

选取不同显示外观但名字相同的截图验证身份稳定性，同时验证素材正确绑定；分别覆盖 Windows/macOS MuMu 的实际缩放。测试真值人工核实，参考/调参/测试集按采集会话分离，避免同图裁剪泄漏。

报告名称整串识别正确率、名称条目候选召回率、错误确定匹配率、待校准比例、素材误绑定次数和修正流程成功率；同名多条允许返回歧义，不能靠猜中算作成功。所有指标附样本数和场景分组，实测后再设数值目标。

回归必须覆盖：无名字页面返回未知、模糊候选不自动确认、换外观不改培养数据、重扫不合并重复持有、取消修正保留旧数据、重新裁剪只替换指定素材、改绑身份标记旧字段待复核。当前仅形成评估方案，尚未执行识别测试。
