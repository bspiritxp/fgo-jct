# 界面风格与功能页面方案

状态：2026-10-15 用户已同意方案，六页界面预览已实现。使用 Naive UI 与 Lucide（当前包名 @lucide/vue），演示数据和界面交互不代表实际游戏功能。

## 视觉方向

采用浅色桌面工具风格：浅灰背景、白色内容面板、中性灰文字、低饱和蓝色强调。游戏元素通过玩家采集的头像、立绘和编队槽位呈现，界面本身保持克制，不采用大面积渐变、金色装饰或复杂纹理。

首版默认浅色，使用主题变量为后续深色模式留出空间。导航以中文为主，去掉现有演示中的装饰性英文副标题。页面标题、操作栏、数据区层级清楚，一页优先突出一个主要操作。

| 项目 | 建议值 | 用法 |
| --- | --- | --- |
| 页面背景 | #F6F7F9 | 全局工作区 |
| 内容背景 | #FFFFFF | 卡片、抽屉、表单 |
| 主文字 | #202833 | 名称、标题、正文 |
| 次文字 | #596674 | 字段标签与说明 |
| 主色 | #356AE6 | 主按钮、选中态、链接 |
| 分隔线 | #E4E7EC | 容器与列表分隔，不作为唯一控件边界 |
| 控件边界 | #8C97A6 | 输入框等需要清晰辨识的边界 |
| 成功/提醒/错误 | #237A4B / #946200 / #C33C3C | 同时搭配文字或图标，不仅靠颜色 |
| 圆角 | 控件 6px、面板 8px | 保持一致 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px | 页面内使用统一刻度 |
| 字号 | 正文 14px、辅助 12px、页面标题 24px | 系统中文字体，不依赖远程字体 |

主体留白适中，信息密度高于宣传网站。阴影仅用于浮层，普通内容靠边框区分。动画以 120–180ms 的状态变化为主，并遵循减少动态效果的系统偏好。

## UI 库建议

推荐 [Naive UI](https://www.naiveui.com/)，搭配 [Lucide](https://lucide.dev/) 的 Vue 图标。Naive UI 适合当前 Vue 3/TypeScript 工程，主题可集中配置，表单、数据表格、抽屉、选择器与反馈组件能覆盖主要需求。

备选 [Element Plus](https://element-plus.org/) 适合偏表格管理的界面；[shadcn-vue](https://www.shadcn-vue.com/) 适合需要更细致定制的界面，但组合和维护成本相对更高。当前建议只引入一套通用组件库，不混用多套基础控件。这是基于组件定位的方案选择，尚未进行安装、体积或 WebView 实测。

通用控件直接使用库组件；只封装有业务含义的 ServantCard、TeamSlot、FieldDiff、CapturePreview 和 CostSummary。公共组件不访问 Gateway，也不导入 ADB/Agent，数据和操作通过 props/events 传递。主题配置放 app/theme，业务组件留在对应 features，确实跨功能复用的组件再放 shared/ui。

## 应用框架

左侧浅色导航约 200px，右侧内容区；顶部为页面标题、当前设备简要状态与主要操作。默认进入从者库，记住列表筛选与视图偏好。设置固定放在导航底部。

主导航：从者库、礼装、编队、采集、战斗助手；底部：设置。名称校准归入采集校对和从者详情，不单独占主导航。关卡首版作为编队内的关联选择器，可新增/编辑本地关卡条目，暂不单独增加关卡管理页面。

```text
┌────────────┬──────────────────────────────────────────┐
│ FGO JCT    │ 从者库                 设备状态   添加档案 │
│            ├──────────────────────────────────────────┤
│ 从者库     │ 搜索名字   职阶筛选   排序   卡片/列表      │
│ 礼装       │                                          │
│ 编队       │ 从者卡片 / 表格                          │
│ 采集       │                                          │
│ 战斗助手   │                           详情抽屉（按需）│
│            │                                          │
│ 设置       │                                          │
└────────────┴──────────────────────────────────────────┘
```

推荐窗口 1180×800，兼容现有最小宽度 760px。宽度不足约 1000px 时导航缩为图标栏（有文字提示和可访问名称），详情改用独立覆盖面板；编队六槽位改成两行，每行三格。表格可横向滚动，关键按钮不能被挤出可视区。主界面不叠加多个同级滚动区域。

## 功能页面

| 页面 | 核心布局 | 主要操作 |
| --- | --- | --- |
| 从者库 | 顶部搜索/筛选，默认头像卡片，可切表格；右侧详情抽屉 | 查看、手工添加、编辑、重新识别、更新素材 |
| 礼装 | 概念礼装/御主礼装两个标签页，列表或卡片，详情抽屉 | 管理持有、等级、突破状态；选择或修正素材 |
| 编队 | 队伍列表进入独立编辑页；六槽位为主体，底部费用摘要 | 从者/礼装选择、助战、御主礼装、排序、保存草稿、关卡关联 |
| 采集 | 顶部选设备，中间截图预览，右侧识别与校对 | 截图、重新识别、名称校准、裁剪、确认写入指定实例 |
| 战斗助手 | 左侧当前截图与时间，右侧状态和建议 | 分析当前画面、重新分析、查看依据与未知项 |
| 设置 | 设备、Agent、数据与外观分组 | ADB 配置/检测、Agent 配置/检测、数据位置与名称资料版本 |

### 从者库与详情

卡片显示用户头像、中文名称、等级、宝具和技能摘要；日文名放详情和搜索结果，避免卡片拥挤。重复持有用可编辑备注或短编号区分。无头像用中性占位，不补官方图片。

详情包括资料、培养信息、素材三个分区；来源和修正记录收在次级展开区。未知字段显示“未知”，待确认字段显示“待校对”。保存修改、重新识别、重新采集素材分别操作，避免换图时连带修改培养数据。

### 礼装

概念礼装展示持有实例、等级、突破状态、COST；御主礼装展示账号拥有状态与等级。概念礼装同名多份独立保存。来自游戏或人工录入的数据有来源提示，未采集的效果不凭空填充。礼装素材同样取自游戏截图。

### 编队编辑

六槽位分前排与后备，每格上方为从者，下方为概念礼装；御主礼装位于队伍级区域。点击空槽位打开可筛选选择面板，同时支持拖拽和按钮调整顺序。替换从者、移除礼装等操作局部完成。

助战明显标记“助战”，区分期望条件和实际观察配置。COST 显示“已用 / 上限”，超限附文字；缺资料显示“信息不足”。费用未知或超限仍可保存草稿，保存不等于游戏内队伍同步。

关卡关联是可选区域；支持选择多关卡、移除关联及新建手工关卡，不强迫先选择关卡再建队。

### 采集与校对

页面内完成“选设备 → 截图 → 识别 → 校对 → 保存”。原图预览可缩放；校对字段点选后高亮来源区域。名称区域展示识别原文、中／日名称候选与手动搜索入口；没有可读名字时提示打开详情页。

用户明确选择新增实例或更新现有实例，展示新旧差异后确认。头像/立绘分别裁剪预览。重新识别与取消不覆盖旧档案；低置信度和同名歧义保留待校对，不静默自动选定。设备离线时仍可浏览已保存档案；手工录入入口始终可见。

### 战斗助手

建议采用结构化步骤列表，每条展示依据；未知状态单列，分析失败时保留截图与重试入口。截图时间明显展示，不声称持续读取游戏。画面可能过期时提示重新分析；不把计划编队直接当成当前实际阵容。

不使用聊天对话作为主要工作区，不提供战斗执行按钮。Agent 的具体实现细节放设置，页面仅展示可用状态与分析结果。

### 设置

设备设置包含 ADB 路径、设备检测与当前目标；Agent 设置包含适配器类型、程序路径或 API 配置、能力检测结果。密钥默认遮盖，不在日志或普通资料表展示。

数据设置展示实际存储位置、官方名称资料来源/版本。备份功能未实现时不显示可用操作。外观设置先提供默认浅色主题，深色切换在实现后再开放。

## 统一交互与状态

- 列表加载用局部骨架或加载指示；长任务展示进度、当前步骤和取消。
- 初次空状态解释下一步，例如“前往采集”或“手工添加”，避免只显示空白。
- 成功保存用简短提示，校验失败紧邻对应字段；断连和任务失败提供具体恢复入口。
- 编辑中离开页面提醒未保存修改；删除被引用对象时展示引用影响。普通浏览和刷新不弹确认框。
- 支持键盘导航与可见焦点，抽屉关闭后焦点回到触发处；拖拽提供按钮替代。
- 字段有文字标签；状态同时使用文字与颜色。实现时检查文本对比度与最小窗口溢出情况。

## 实施顺序

1. 引入 UI 库、主题变量和应用布局，调整主导航。
2. 完成从者库/详情与采集/校对的第一条交互链。
3. 增加礼装与完整编队编辑页。
4. 完成战斗助手与设置；接入真实能力时补足加载、错误、取消和修正流程。

演示数据与未接入状态持续明确展示，视觉改版不改变现有 Gateway/应用用例边界。

## 已实现的界面预览

六个页面：从者库、礼装、编队、采集、战斗助手、设置。支持从者搜索/筛选、卡片/列表、详情抽屉、礼装标签页、队伍槽位选择、设置分组及建议布局演示。头像与立绘用统一占位图形，不下载官方图片。

演示资料位于 `apps/desktop/src/preview/data.ts`，与正式数据契约/仓储隔离。Naive UI 主题位于 `app/theme/`，通用素材占位位于 `shared/ui/`，六页各自位于对应 feature 目录。保存、设备检测与采集不执行真实操作。

运行 `pnpm dev` 后访问 `http://localhost:1420`。浏览器交互测试见 `tests/ui/preview.spec.ts`，覆盖页面导航、搜索、详情抽屉、编队选人和窄窗口无横向溢出。

### 从者卡片尺寸调整

已按用户确认改为左侧固定 80×80px 头像、右侧名称/职阶/培养摘要的横向卡片，高约 120px；列数随窗口自适应。详情大图、礼装素材不随此调整缩小。
