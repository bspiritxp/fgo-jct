## 讨论记录

首轮答复已同步至需求、设计、架构与路线。当前建议采用 Rust 直接管理外部 CLI 子进程，降低初期实现和打包复杂度；具体适配器需核实用户安装版本。第二轮已确认采集方式和完整编队范围，同步更新需求、设计、架构、数据模型及路线。礼装录入方式、COST 上限来源和助战条件模型为实现建议；下一轮优先讨论 Agent 和图鉴数据来源。

第三轮确认接受公开图鉴并要求评估多外观识别风险。新增评估方案和分离身份/外观/持有实例的数据设计；尚未采集真实样本或完成准确率测试。

第四轮以名称校准方案替代第三轮多外观检索建议：不建立官方或本地头像身份模板库。COST 等已确认功能保留，规则资料先以游戏可见信息识别/人工录入维护是实现建议，外部规则导入未定。当前识别评估文档已按新方案重写。
